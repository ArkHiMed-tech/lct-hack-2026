# Чек-лист проверки ответов оператора — система 112

# (на основе регламентированного протокола приёма и обработки вызовов МЧС / ЦОВ-112)

Основание: порядок приёма и обработки вызовов в единой дежурно-диспетчерской службе (ФЗ-151, ФЗ-339 «Система-112», методические рекомендации МЧС России, форма «карточки вызова»). Используется как рубрика оценивания тренировки в симуляторе.

---

## 1. Структура и правила

- Чек-лист состоит из 6 групп **A–F**; каждая состоит из пунктов.
- Каждый пункт имеет: `ID`, формулировку, **тип проверки**, **вес** (доля группы), правило оценивания.
- Типы проверки:

| Тип | Смысл |
|-----|-------|
| `text` | Оператор ввёл текст, содержащий требуемые элементы (адрес, служба и т.п.) |
| `key_extract` | Из ответа оператора автоматически извлекается факт (адрес, число пострадавших, № телефона) и сравнивается с эталоном |
| `option` | Выбрано одно из заданных решений (служба передачи, категория ЧС) |
| `timing` | Событие произошло в пределах временного окна (ответ на вызов) |
| `order` | Действие выполнено раньше/позже другого (например, завершение не раньше передачи) |
| `forbidden` | Запрещённые действия/фразы — вычитание баллов |

- Группа «вычитания» применяется к любому пункту списку `forbidden`.

## 2. ГРУППА A — Приём вызова

| ID | Критерий | Тип | Вес | Правило |
|----|----------|-----|-----|---------|
| A1 | Ответ на вызов в течение не более 8–10 секунд (не более 1–2 сигналов) | `timing` | 0.35 | Таймер от поступления до нажатия «Ответить» ≤ 8 c (настраивается в сценарии) |
| A2 | Приветствие и наименование службы: «Единая служба спасения (112). Диспетчер [Фамилия], слушаю вас» | `text` | 0.40 | В первой реплике оператора присутствуют: наименование службы (112/служба спасения) + «слушаю» |
| A3 | Представление: названа фамилия диспетчера | `text` | 0.25 | Фамилия из профиля пользователя присутствует в первой реплике |

> Пункт «Голос/тон оператора» (бывший A4) временно исключён из оценивания до подключения модели/ручной проверки.

## 3. ГРУППА B — Идентификация звонящего и локализация места происшествия

| ID | Критерий | Тип | Вес | Правило |
|----|----------|-----|-----|---------|
| B1 | Уточнены ФИО звонящего | `key_extract` | 0.15 | ФИО абонента получено и совпадает/записано |
| B2 | Уточнён контактный телефон (если не определился автоматически по АОН) | `key_extract` | 0.10 | Телефон введён/подтверждён |
| B3 | Получен точный адрес: населённый пункт, улица, дом, корпус, квартира, подъезд, этаж | `key_extract` | 0.30 | Извлечены все маркеры адреса, указанные в сценарии |
| B4 | Проверка/повтор адреса оператором («…продиктуйте адрес ещё раз», «Я вас понял, адрес…» + подтверждение абонента) | `order`+`text` | 0.20 | Адрес упомянут в реплике оператора и подтверждён абонентом |

Обязательные вопросы («7 ключевых»): что случилось / где / когда / кто пострадал / сколько / есть ли угроза жизни / кто звонит.

| ID | Критерий | Тип | Вес | Правило |
|----|----------|-----|-----|---------|
| C1 | Задан вопрос «Что случилось?» и получено описание характера происшествия | `text` | 0.15 | Определены ключевые слова категории ЧС (пожар, ДТП, плохо человек, запах газа…) |
| C2 | Уточнено количество пострадавших (в т.ч. «пострадавших нет») | `key_extract` | 0.15 | Число извлечено из ответа абонента |
| C3 | Уточнено состояние пострадавших: сознание, дыхание, видимые травмы, кровотечение | `text` | 0.15 | Наличие вопросов/фиксации по состоянию |
| C4 | Установлено наличие угрозы жизни и здоровью (в т.ч. угроза для самого абонента) | `text` | 0.12 | Явно спрошено/зафиксировано |
| C5 | Выявлены опасные факторы: открытое пламя/дым, запах газа, разлив опасных веществ, угроза обрушения/взрыва | `text` | 0.12 | Спрашивался хотя бы один из факторов, релевантный сценарию, либо абонент сообщил и оператор уточнил |

| C7 | Спрошено, что уже предпринято абонентом (эвакуация, первая помощь, тушение подручными средствами) | `text` | 0.11 | Вопрос или фиксация действий абонента |
| C8 | Переданные/сообщённые координаты совпадают с эталоном сценария (false/true для геометки) | `key_extract` | 0.10 | Совпадение координат/адреса |

## 8. Грубые (критические) ошибки — автоматический незачёт или сильный штраф

| ID | Ошибка | Следствие |
|----|--------|-----------|
| X1 | Оператор не назвал службу/не представился в первой реплике | Штраф группы A; критично |
| X2 | Не уточнён адрес происшествия | Критично → незачёт |
| X3 | Вызов не передан ни в одну экстренную службу | Критично → незачёт |
| X4 | Вызов передан в службы, не соответствующие категории (например, полиция вместо скорой) | Критично → незачёт |
| X5 | Грубость, повышение голоса, прерывание абонента без необходимости (детект по тексту/модели) | Вычитание 50% итога |
| X6 | Завершение вызова без передачи и без инструктажа | Критично → незачёт |
| X7 | Предоставление абоненту недостоверной/небезопасной инструкции (противоречащей протоколу) | Вычитание 40% итога, ручная отметка |

## 9. Подсчёт итога

- `score_group(X) = Σ (пункт выполнен ? вес : 0) × 100`.
- Итог: `score_total = Σ группы (score_group × weight_group)`, где веса групп по умолчанию:
  A 0.10 · B 0.20 · C 0.25 · D 0.20 · E 0.10 · F 0.15 (настраивается в рубрике).
- Оценка: ≥ 80% — «зачёт/отлично»; 60–79% — «зачтено»; < 60% или любая критическая ошибка X — «не зачтено».
- Рубрика хранится машиночитаемо (см. `JSON-CONTRACT.md`) и редактируется в админ-панели (страница 8).

## 10. Примечание для конструктора сценариев
При создании сценария задаются: категория ЧС → активирует подгруппы D (пожар/медицина/газ/ДТП), эталонные значения для `key_extract` (адрес, ФИО, телефон, число пострадавших, время), перечень `expected_services`, тайм-аут ответа A1 и пороги оценок.
