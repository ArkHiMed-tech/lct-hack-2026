# Учебный тренажёр оператора ДДС (Система-112) с ИИ

# Спецификация пользовательского интерфейса

Статус: приведено в соответствие с `PLAN.md` (2026-09-19, источник — папка `/workspace/TZ`:
ТЗ финал 01.09.2026, Инструкция по заведению карточки, Памятка АРМ-112 для ДДС,
Классификатор происшествий v046 (2 версии), Билеты-задачи С112, datasheet РТУ Т16Р,
скриншоты карточки/ДДС).
Контур: изолированный, без доступа к внешним сетям. Интеграция с бэкендом (FastAPI) —
через внутренний API собственных модулей (см. `API.md`, `JSON-CONTRACT.md`);
внешних интеграций нет. Форматы: JSON (обмен/профили/сценарии/логи), XML (конфиги/методички),
SQL (PostgreSQL 12+), аудио MP3/WAV, документы PDF/DOCX, выгрузка CSV/PDF/JSON.

журналы безопасности ≥ 6 мес. Ограничения по ТЗ: не обрабатывать реальные вызовы,
не содержать боевое ПО Системы-112, не работать с ПДн вне учебного процесса.

## 3. Подробное содержание страниц

### 3.1. Авторизация
- Поля: логин + пароль + номер АРМ (по Инструкции по заведению карточки); выбор роли.
- Действия: «Войти» (Enter); автовыход при простое (ориентир 24 ч); аудит входов.
- Атрибуты: форма, кнопка, блок ошибок ввода; после входа — проверка подключения к телефонии.
- Подсказка при сбоях приёма вызовов / переключения статуса «доступен»: `Ctrl+F5`, повторный вход, обращение в техподдержку.
- Источники: `POST /api/auth/login`, `users.json`, `roles.json`.

### 3.2. Главная обучающегося
- Приветствие с ФИО и ролью.
- Карточки сценариев: название, категория ЧС (значок), сложность, статус (новый / в процессе / завершён), лучший результат.
- Кнопка «Начать/Продолжить тренировку».
- Блок «Моя статистика»: средний балл, число тренировок, последний результат.
- Атрибуты: сетка карточек, фильтр по категории, прогресс-бары.

### 3.3. Рабочее место диспетчера (симуляция) — центральная страница
Поток: входящий «звонок» (окно с кнопкой «Принять») → оператор отвечает (норматив
`sla_answer_sec` 8–10 сек, дефолт 8) → диалог с абонентом → сбор обязательной информации →
заполнение всех блоков карточки (норматив `sla_card_sec` — дефолт 30 сек; при превышении
поле подсвечивается красным, по скриншоту карточки) → выбор служб (ТЭГи → автослужбы +
ручное добавление) → передача вызова в службы ДО завершения → завершение.
Таймер карточки: старт при открытии, стоп по «Сохранить»; время идёт в отчёты.
Допускается частичное заполнение блоков с возвратом. Опции вызова: перевод в службу,
исходящий заявителю/в службы, перевод другому оператору, hold/завершение, опции аппарата.
СМС-канал: входящие СМС + переписка с заявителем в карточке.

Состоит из панелей (см. раздел 4, атрибуты C1–C12) + блоков карточки АРМ-112:
- `Телефоны (Alt+F1/F2/F3)`: АОН авто + предоставленный + на место; кнопка «АОН» для копирования при совпадении; признак «зарубежный номер» (не +7); сообщение при вызове без SIM; канал связи (выпадающий список + поиск, автоопределение для Теле2/МТС/Мегафон/Билайн); ФИО заявителя + статус + признак иностранного языка; название внешней системы (ВИС); кнопки «Нет контакта» / «Срыв звонка» (пустая карточка → статус «Завершена», признак «Проверено»).
- `Что случилось (Alt+T)`: выбор сценария из Классификатора v046 (~50 типов: 101/102/103/104, ДТП, пожары, медицина, газ и пр.) тремя способами — частые плашки, значимые типы, строка поиска («добавить тип происшествия», синонимы: пожар/взрыв/обрушение/ДТП/запах газа и пр., мульти-выбор); ТЭГи под сценарий → автовыбор служб + ручное добавление; признак «Отказ от реагирования» (напр. карточка 103).
- `Адрес (Alt+A)`: единая адресная строка (дом в той же строке) → варианты Яндекс.Карты / Яндекс.Организации / ФИАС → карта в отдельном окне 1:50 + кнопка «Указать на карте» (геометка → автозаполнение полей); поля город/улица/дом/корпус/квартира/подъезд/этаж + округ/район (с поиском) + справочник соцобъектов + ориентиры/пути подъезда/подтверждение повтором; кнопка очистки. Особенность: при адресе ФИАС службы не подтягиваются — добавлять вручную.
- `Подробности`: описание со слов заявителя (кратко, без слухов); ФИО + статус; контактный телефон; время происшествия; пострадавшие (число/состояние: сознание, дыхание, травмы, кровотечение); угроза жизни; опасные факторы; что предпринято заявителем; доступность для спецтехники.
- Службы на вызов: пожарная, скорая, полиция, газовая, городская + профильные (Гормост, жилищные, Мосводоканал, Москоллектор, Управы и пр.); связи между карточками, дополнения, отработка, окончание, напоминание/привлечь внимание, сообщение об ошибке.
- Горячие клавиши (по Инструкции): Alt (подсказки), Insert (новая карточка), Esc (закрыть), Tab/Shift+Tab, Alt+F1/F2/F3 (телефоны), Alt+K (канал), Alt+Q (заявитель), Alt+A (адрес), Alt+P (пострадавшие), Alt+N (нет контакта/срыв).

### 3.3.1. Рабочее поле ДДС (сторона исполнителя, по Памятке и скриншоту ДДС)
- Рабочее поле ДДС + строка сообщений + карточка ДДС + поле статуса.
- Статусы: Принято / Не принято (ручной выбор + ручные поля); далее через «карандашик»: Начало реагирования / Отказ от выполнения / Работы завершены + комментарий. Подтверждение получения сообщения — через 30 сек после направления в службу (нормативка, Памятка).

### 3.4. Результаты тренировки
- Итоговый балл (проценты) и вердикт: ≥ 80 — «отлично», 60–79 — «зачтено», < 60 или любая X-критика — «не зачтено» (веса групп A 0.10 / B 0.20 / C 0.25 / D 0.20 / E 0.10 / F 0.15).
- Сводка по группам чек-листа A–F+X: радиальная/линейная диаграмма; время ответа vs `sla_answer_sec`, время карточки vs `sla_card_sec` (дефолт 30 сек), грамматика ручного ввода vs эталон.
- Список несобранных пунктов чек-листа с пояснением «что должно было быть» и ссылкой на момент диалога.
- Дерево диалога: реплики абонента/оператора с подсветкой эталонных/ошибочных; сравнение ручного ввода с эталоном, контроль порядка (передача до завершения), запрещённые фразы.
- Экспертная оценка и комментарии преподавателя поверх автооценки (с аудитом правок).
- Действия: «Повторить», «Вернуться на главную».
- Источники: `results/<session_id>.json` + `rubrics/<id>.json`.

### 3.5. Журнал успеваемости и отчёт занятия
- Таблица: дата, сценарий, категория, время ответа, время карточки vs норматив, балл, оценка.
- Фильтры по дате/категории/сценарию/пользователю/группе, сортировка, экспорт CSV/PDF/JSON (время формирования ≤ 30 сек).
- Для преподавателя: список обучающихся с агрегированными показателями; мониторинг выполнения realtime (кто на какой карточке, таймеры, завершение/пауза); отчёт занятия (действия, замечания, время vs норматив, грамматика); ИИ-инсайты: типичные ошибки группы, тепловые карты ошибок, рекомендации.

### 3.6–3.8. Админ-панели и панели преподавателя
- Списки (таблицы) с CRUD-формами и модальными окнами.
- Конструктор сценария (страница 7): категория → подгруппа инструктажа D (пожар/медицина/газ/ДТП); редактор таймлайна реплик абонента (время + текст + тон + эмоция + набор «ожидаемых действий»), эталонные значения (адрес, ФИО, телефон, число пострадавших, время, координаты), `expected_services`, quick replies/подсказки, уровни сложности, `sla_answer_sec` (8–10), `sla_card_sec` (дефолт 30), пороги оценок; нейрогенерация + автоэталон; предпросмотр с подсветкой правильных; поле коррекции; validate/отклонение; загрузка материалов; проверка грамматики; назначение группам; ролевая фильтрация ленты.
- Редактор рубрик (страница 8): добавление/изменение групп и пунктов чек-листа A–F+X, весов и типов проверки (`text`/`key_extract`/`option`/`timing`/`order`/`forbidden`).
- Панель администратора (страница 6): состояние сервисов realtime, производительность, пакетные обновления, бэкап/восстановление, SIP/БД/безопасность/логи; журналы, статистика, ошибки, нагрузка.

## 5. Пользовательские потоки (по PLAN §6 + сценарии ТЗ)

### Поток A — настройка учебной среды (преподаватель)
1. Вход через защищённый интерфейс локального комплекса.
2. Выбор категории событий (мульти) → настройка нейросети на генерацию типов происшествий (ДТП, пожары, медицина и пр.) по теме занятия.
3. Автоформирование «эталона» → подтверждение (частичное/полное) преподавателем.
4. Ролевая модель: в ленту обучающихся попадают только профильные события.
5. Предпросмотр вопросов/ответов с подсветкой правильных → коррекция через контекстное поле → пересбор; при необходимости обучение загрузкой материалов; принудительная проверка грамматики.

### Поток B — занятие «карточки» (преподаватель + обучающиеся)
1. Вход на странице 1 → роль «Обучающийся» (логин/пароль/номер АРМ).
2. Главная (страница 2): выбор назначенного сценария → «Начать».
3. Симуляция (страница 3):
   - `CallTimer` стартует (SLA ответа 8 сек, SLA карточки 30 сек), `LineStatus` = ringing/доступен, `CallInfoPanel` получает данные звонка (АОН авто);
   - оператор нажимает «Ответить» → `LineStatus` = connected, `ChatInput` активен;
   - абонент «говорит» (реплики в `CallFeed`/СМС по таймлайну: время + текст + тон + эмоция + ожидаемые действия);
   - оператор печатает реплики / использует `QuickReplyPanel`; система в фоне оценивает покрытие чек-листа (`ChecklistProgress` A–F+X);
   - оператор заполняет `IncidentForm` (все блоки обязательны, частичное заполнение разрешено), выбирает службы в `DispatchPanel` (ТЭГи → авто + вручную);
   - «Передать в службы» (ДО завершения) → «Сохранить» (стоп таймера) → «Завершить».
4. Переход на страницу результатов (4): разбор по `results/<session_id>.json` (балл, вердикт, время vs норматив, грамматика, дерево диалога).
5. Журнал (5) хранит историю; преподаватель завершает занятие и формирует отчёт (действия, замечания, время vs норматив, грамматика) + CSV/PDF.
6. Минимальный демо-путь приёмки: преподаватель создаёт тему → генерирует → утверждает → назначает → запускает; обучающийся принимает ≤ 8 сек, заполняет ≤ 30 сек (просрочка краснеет); система считает A–F+X; преподаватель видит мониторинг/отчёт/топ ошибок; администратор видит сервисы/журналы/бэкап; всё в аудите.

### Поток C — занятие «действия с карточками» (сторона ДДС)
1. Выбор преподавателем источника: сгенерированные / сформированные обучающимися / смешанные.
2. Система выдаёт случайную карточку → обучающийся выполняет действия + ввод текста (напр. «Сообщение принято, бригада направлена») → следующая карточка → завершение преподавателем в любой момент + отчёт.

## 6. Допущения и нефункциональные требования для интеграции

- Данные — через внутренний API собственных модулей (контракт `JSON-CONTRACT.md`); JSON-файлы `public/data/*` — только сид прототипа с переездом в БД. Внешних интеграций нет; импорт пакетных обновлений — вручную.
- Оценка ответов выполняется бэкендом по рубрике A–F+X; фронт получает уже вычисленные баллы и «пропуски», выполняет только отображение.
- Определение «покрыл/не покрыл» пункта чек-листа допускается и на фронте (черновой режим), но авторитетным считается расчёт бэкенда при сохранении результата (сравнение ручного ввода с эталоном, тайминг/порядок, запрещённые фразы, грамматика).
- Временные метки (мс, UNIX / ISO 8601 UTC) — единый формат; таймеры фронта синхронизируются со стартом сессии из JSON сценария (`sla_answer_sec` 8–10, `sla_card_sec` 30).
- Карта: окно 1:50 + «Указать на карте»; в прототипе допустима карта-заглушка (текстовая панель адреса + геометка).
- Производительность (локальная сеть): отклик ≤ 2 сек при 100 пользователях; запись БД ≥ 100 оп/с; отчёт ≤ 30 сек; голос ≤ 150 мс; живучесть при обрыве до 30 сек (буферизация, автовосстановление без потери); 20 одновременных сессий.
- Надёжность: бэкап ≥ 1 р/сутки, отказоустойчивость узлов кластера, автовосстановление сервисов, мониторинг realtime, журнал значимых событий.
- Совместимость: Ubuntu 20.04+ / Windows 10/11, Chrome/Firefox/Яндекс.Браузер актуальные, PostgreSQL 12+, локальный SIP. Железо: АРМ i5/16 ГБ/SSD256/Gigabit/гарнитура VoIP; сервер ИИ i7/Xeon 6+ ядер/32 ГБ/NVMe512.
- Адаптив: десктоп + мобильные в локальной сети; русский язык; единая стилистика; каждый элемент — только под задачу пользователя.
- Документация/право: методы обработки данных, условия/ограничения, сборка/установка, функциональная и компонентная архитектура, перечень библиотек, процедуры установки/восстановления/диагностики; код открытый без обфускации; презентация pptx/pdf; соблюдение 149-ФЗ, 152-ФЗ, ГОСТ КСАС.
