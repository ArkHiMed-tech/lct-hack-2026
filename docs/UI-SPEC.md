# Учебный симулятор диспетчеров экстренных служб (система 112)

# Спецификация пользовательского интерфейса — задача 01

Статус: черновик для обсуждения. Интеграция с бэкендом (FastAPI) — через JSON-файлы (см. `JSON-CONTRACT.md`).

## 1. Роли пользователей

| Роль | Возможности |
|------|-------------|
| Обучающийся (стажёр-диспетчер) | Прохождение сценариев-тренировок, просмотр своих результатов и разбора ошибок |

## 3. Подробное содержание страниц

### 3.1. Авторизация
- Поля: ФИО/логин, выбор роли (для учебной системы пароль опционален).
- Действия: «Войти».
- Атрибуты: форма, кнопка, блок ошибок ввода.
- Источники: `users.json`, `roles.json`.

### 3.2. Главная обучающегося
- Приветствие с ФИО и ролью.
- Карточки сценариев: название, категория ЧС (значок), сложность, статус (новый / в процессе / завершён), лучший результат.
- Кнопка «Начать/Продолжить тренировку».
- Блок «Моя статистика»: средний балл, число тренировок, последний результат.
- Атрибуты: сетка карточек, фильтр по категории, прогресс-бары.

### 3.3. Рабочее место диспетчера (симуляция) — центральная страница
Поток: входящий «звонок» → оператор отвечает → диалог с абонентом → сбор обязательной информации → передача вызова в службы → завершение.

Состоит из панелей (см. раздел 4, атрибуты C1–C12).

### 3.4. Результаты тренировки
- Итоговый балл (проценты) и оценка (зачёт/незачёт).
- Сводка по группам чек-листа: радиальная/линейная диаграмма.
- Список несобранных пунктов чек-листа с пояснением «что должно было быть» и ссылкой на момент диалога.
- Дерево диалога: реплики абонента/оператора с подсветкой эталонных.
- Действия: «Повторить», «Вернуться на главную».
- Источники: `results/<session_id>.json` + `rubrics/<id>.json`.

### 3.5. Журнал успеваемости
- Таблица: дата, сценарий, категория, время ответа, балл, оценка.
- Фильтры по дате/категории/сценарию, сортировка, экспорт.
- Для преподавателя: список обучающихся с агрегированными показателями.

### 3.6–3.8. Админ-панели
- Списки (таблицы) с CRUD-формами и модальными окнами.
- Конструктор сценария (страница 7): редактор таймлайна реплик абонента (время + текст + тон + эмоциональность + набор «ожидаемых действий»), выбор категории, требуемых служб и синхронизация с рубрикой оценки.
- Редактор рубрик (страница 8): добавление/изменение групп и пунктов чек-листа, весов и типов проверки.

## 5. Пользовательский поток (главный сценарий)

1. Вход на странице 1 → роль «Обучающийся».
2. Главная (страница 2): выбор сценария → «Начать».
3. Симуляция (страница 3):
   - `CallTimer` стартует, `LineStatus` = ringing, `CallInfoPanel` получает данные звонка;
   - оператор нажимает «Ответить» → `LineStatus` = connected, `ChatInput` активен;
   - абонент «говорит» (реплики появляются в `CallFeed` по таймлайну сценария);
   - оператор печатает реплики / использует `QuickReplyPanel`; система в фоне оценивает покрытие чек-листа (`ChecklistProgress`);
   - оператор заполняет `IncidentForm`, выбирает службы в `DispatchPanel`;
   - «Передать в службы» → завершение активной фазы; «Завершить».
4. Переход на страницу результатов (4): разбор по `results/<session_id>.json`.
5. Журнал (5) хранит историю.

## 6. Допущения для интеграции

- Все данные приходят из JSON-файлов по фиксированным путям (конфиг в `config.json`).
- Оценка ответов выполняется бэкендом по рубрике; фронт получает уже вычисленные баллы и «пропуски», выполняет только отображение.
- Определение «покрыл/не покрыл» пункта чек-листа допускается и на фронте (черновой режим), но авторитетным считается расчёт бэкенда при сохранении результата.
- Временные метки (мс, UNIX) — единый формат; таймеры фронта синхронизируются со стартом сессии из JSON сценария.
- Наличие/отсутствие карты (геопортал) решается отдельно — исходно панель адреса текстовая.
